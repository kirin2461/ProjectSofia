# Браузер и автономный режим

Как София ходит по сайтам от вашего лица, чем отличается от «кликов по картинке»,
где проходит граница самовольности и что она физически не умеет.

## 1. Чем управляем: настоящий Chrome через CDP

`modules/browser_agent.py` поднимает установленный Chrome с портом отладки и
говорит с ним по DevTools Protocol (WebSocket).

Почему не пиксели и не `pyautogui`:

| Подход | Что видит модель | Итог |
|---|---|---|
| скриншот + поиск кнопки по картинке | цветные пятна | 4B-модель промахивается, координаты «плывут» при смене масштаба |
| CDP (выбрано) | настоящий DOM: текст, ссылки, поля | «нажми Войти» работает на любом сайте и в headless |

Клик — не подделка события в JS, а `Input.dispatchMouseEvent`: браузер считает
его настоящим вводом, поэтому работают меню, `:hover`, проверки «клик человека».
Ввод текста — `Input.insertText`, кириллица не превращается в мусор.

Соединение синхронное (`websockets.sync`) и живёт в рабочем потоке: сервер
остаётся отзывчивым, пока страница грузится.

## 2. Профили Chrome

`BROWSER_PROFILE`:

- `sofia` (по умолчанию) — отдельная папка `data/browser/sofia`. Ваш основной
  Chrome не трогается, входы на сайтах сохраняются между запусками.
- `user` — ваш профиль, со всеми входами и закладками. Chrome отдаёт порт
  отладки только при старте, поэтому **основной браузер придётся закрыть**:
  иначе запустится второй процесс с залоченным профилем.

Если на порту уже висит Chrome (например, София его не закрыла), `start()`
не падает, а подключается к нему. Если порт занят чужим процессом — понятная
ошибка, а не таймаут.

## 3. Действия

Внутри — один словарь на действие, снаружи — один JSON:

| Действие | Пример | Как выполняется |
|---|---|---|
| `navigate` | `{"action":"navigate","url":"https://…"}` | `Page.navigate` + ожидание `readyState` |
| `click` | `{"action":"click","text":"Войти"}` | поиск по видимому тексту → координаты центра → настоящий клик |
| `type` | `{"action":"type","field":"Поиск","text":"Сивухин","enter":true}` | фокус в поле → `Input.insertText` → `Enter` |
| `press` | `{"action":"press","key":"Enter"}` | `Input.dispatchKeyEvent` |
| `scroll` | `{"action":"scroll","dy":900}` | колесо мыши в центре страницы |
| `read` | `{"action":"read"}` | текст страницы (до 3000 символов) |
| `open_tab` / `switch_tab` / `close_tab` | `{"action":"open_tab","url":"…"}` | вкладки через `Target.*` |
| `back` | `{"action":"back"}` | `history.back()` |
| `done` / `ask` | `{"action":"done","summary":"…"}` | конец прогона |

Поиск по тексту (`_FIND_JS`) идёт по кнопкам, ссылкам, `[role=button]` и
`input[type=submit]`, отдаёт координаты и умеет `scrollIntoView`. Совпадение —
подстрока без учёта регистра, при нескольких кандидатах берётся самый короткий
текст: «Войти» важнее, чем «Войти в личный кабинет через Госуслуги».

## 4. Автономный режим

`modules/autopilot.py`. Цель формулируется словами, дальше цикл:

```
страница (текст + адрес + история шагов) → модель → один JSON → действие → результат
```

- **Один шаг за раз.** Просить 4B-модель «управлять браузером» целиком — путь
  к галлюцинациям. Выбрать одно действие из списка она умеет надёжно.
- **Бюджет шагов** — `AUTOPILOT_MAX_STEPS` (12 по умолчанию).
- **Защита от циклов.** Два одинаковых действия подряд (или два провала
  одного действия) останавливают прогон с внятной причиной.
- **Проверка перед `done`.** Перед финалом она читает страницу и сверяет
  результат с целью; если не сходится — продолжает.
- **`ask`** — честный выход: «без человека не обойтись» (капча, пароль,
  двухфакторный код).

Живой прогон на локальном сайте (модель Gemma-4-E4B, 3 шага, 9.2 с):

```
шаг 1: ✓ navigate http://127.0.0.1:8767/
шаг 2: ✓ click Показать секрет
шаг 3: ✓ read
готово: нажата кнопка, текст подтверждает секрет
```

## 5. Барьер: деньги и отправка

`AUTOPILOT_BARRIER=True` (по умолчанию). Прогон останавливается и спрашивает
разрешение только в двух случаях (`needs_confirmation`):

- **деньги** — оплата, покупка, подписка, «купить», «оплатить», «₽», страницы
  оплаты в адресе;
- **отправка от вашего имени** — «отправить», «подать заявку», «подписать»,
  «разместить объявление».

Всё остальное (читать, искать, листать, открывать вкладки, заполнять поля без
отправки) — без вопросов, иначе автономность бессмысленна.

Тонкость, которая уже стоила отладки: при вводе текста проверяется только
**куда** вводят (подсказка поля и адрес страницы), а не сам текст. Иначе
обычный набор в поле на странице с «post» в адресе требовал бы подтверждения.

Ответ на запрос — `POST /api/autopilot/confirm {"allow": true|false}`;
кнопки есть в панели «Браузер».

## 6. Экран и курсор — отдельный слой

`modules/screen_control.py` нужен, когда действие не в браузере, а в обычной
программе: скриншот всех мониторов (`ImageGrab`), движение мыши, клик,
юникод-ввод через `SendInput`.

Главное правило: **если человек за компьютером, София уступает.**
`user_is_active()` смотрит `GetLastInputInfo`; перед действием —
`wait_for_user_idle(threshold, timeout)`, и если вы не отпустили мышь и
клавиатуру, действие не выполняется.

Браузером София управляет через CDP и курсор при этом **не двигает** — можно
спокойно работать, пока она листает сайт в своём окне.

## 7. API и интерфейс

| Метод | Что делает |
|---|---|
| `GET /api/browser/state` | запущен ли, адрес, заголовок, профиль, идёт ли автопрогон |
| `POST /api/browser/open {"url": …}` | запустить Chrome и открыть адрес |
| `POST /api/browser/close` | закрыть (закрывается только браузер Софии) |
| `GET /api/browser/screenshot` | PNG текущей страницы |
| `POST /api/autopilot {"goal": …, "url": …, "max_steps": …}` | запустить прогон |
| `POST /api/autopilot/stop` | остановить |
| `POST /api/autopilot/confirm {"allow": …}` | ответ на запрос подтверждения |
| `GET /api/autopilot/state` | состояние и журнал шагов (60 последних) |
| `GET /state` | блок `browser` в общей сводке |

В интерфейсе — кнопка «Браузер» в шапке: адрес и заголовок страницы,
поле цели, «Автономно» (старт), «Стоп», карточка подтверждения и журнал
шагов с временем.

## 8. Настройки

`.env` или `config/settings_local.py`:

```
BROWSER_ENABLED=True
BROWSER_PORT=9222
BROWSER_PROFILE=sofia        # sofia | user
AUTOPILOT_MAX_STEPS=12
AUTOPILOT_BARRIER=True
```

Chrome нужен установленный (на машине разработки — 158.x). Порт берётся
свободный, если 9222 занят.

## 9. Чего она не умеет — честно

- **Капчи и 2FA** — только `ask`.
- **Сайты, которые рисуют всё на `<canvas>`** — текста в DOM нет, клик по
  тексту не найдётся; поможет только скриншот и координаты, а это ненадёжно.
- **Длинные формы** — 4B-модель теряет поля; она читает страницу заново после
  каждой ошибки, но бюджет шагов не бесконечен.
- **Сложные рассуждения о цене и выгоде** — это уже не про браузер, а про
  модель: 4B путает валюты и условия. Барьер на деньги здесь не формальность.

## 10. Проверка

```
.venv/Scripts/python.exe -m pytest tests/unit/test_browser_agent.py tests/unit/test_autopilot.py tests/unit/test_screen_control.py -q
```

Тесты поднимают поддельный CDP-сервер и поддельный `user32`, поэтому идут без
Chrome и без GPU. Живой прогон — `probe_browser.py` / `probe_autopilot_live.py`
в временной папке: локальный сайт на `127.0.0.1`, настоящий Chrome, настоящая
модель.
