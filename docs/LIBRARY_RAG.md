# Библиотека книг, память и сжатие контекста

Как София учится по вашим PDF (физика, математика, профессиональные книги),
почему поиск гибридный, что такое кеш промпта и зачем сжимать историю
диалога.

## 1. Задача

Книги лежат в `data/library/`. Она должна:

- читать **и текстовые PDF, и сканы** (в библиотеке смешано);
- находить нужный абзац по смыслу и по терминам («тензор энергии-импульса»);
- ссылаться на источник: «Сивухин, т. 1, с. 112», а не «где-то было»;
- молчать, если в книгах этого нет (не выдумывать цитаты);
- отвечать быстро при длинном диалоге.

Полного дообучения внутри программы нет: 4B-модель на ноутбуке не переучится
за ночь. Работают две вещи: **RAG** (поиск фрагментов → промпт) и стиль
(отдельный LoRA, см. `docs/LORA_STYLE.md`).

## 2. Индексация

`memory/library_ingest.py`, запуск — фоновый `scan_library()` при старте и
кнопка «Книги» в интерфейсе.

```
PDF → страницы (текст или OCR) → чистка → чанки → эмбеддинги → Chroma
```

- **Повторная индексация** пропускается: считается хеш файла и время
  изменения (`file_hash` + `stamp`). Тронули файл — переиндексируется.
- **Чистка.** Убираются колонцифры, повторяющиеся колонтитулы (строки,
  совпадающие на большинстве страниц), переносы слов (`энтро-\nпия` →
  `энтропия`), типографские пробелы (`\xa0`, `\u2009` и другие). Последнее —
  реальный баг: слова с узким пробелом не находились по обычному запросу.
- **Чанкинг по убыванию надёжности:**
  1. оглавление PDF (`get_toc`) → главы с настоящими названиями и страницами;
  2. заголовки в тексте (короткая строка, нумерация «§ 12», «Глава 3»);
  3. постраничная нарезка: чанк не переходит границу страницы, поэтому
     цитата указывает реальный диапазон («с. 45–46»), а не «с. 1–500»;
  4. если главы нет — поле `chapter` остаётся пустым. Выдуманное «Часть 1»
     выглядело бы как ссылка, но ею не является.

## 3. OCR для сканов

Сканы (и страницы, где текстового слоя почти нет — порог `OCR_MIN_CHARS`)
распознаются Tesseract 5:

- страница рендерится в PNG при 300 dpi (`pymupdf`), отдаётся в
  `tesseract stdin stdout -l rus+eng --psm 3`;
- **русский и английский только** — остальные языки не тянутся ни в сборку,
  ни в распознавание: книги на них всё равно не читаются;
- поиск бинарника: `TESSERACT_CMD` → `bin/tesseract` внутри сборки →
  `bin/tesseract` рядом с `.exe` → `PATH`;
- нет Tesseract — в лог одно предупреждение, сканы остаются без текста,
  остальное работает.

В сборку `Sofia.exe` Tesseract входит целиком (exe + DLL + `rus`/`eng`
traineddata, ~183 МБ): пользователю не нужно ничего ставить.

## 4. Эмбеддинги

`memory/embedder.py`. Модель — **multilingual-e5-small** (ONNX, квантованная,
113 МБ, 384 измерения), работает на CPU через onnxruntime.

Почему не встроенная в Chroma `all-MiniLM-L6-v2`: она обучена на английском,
и на русских книгах выдача близка к случайной. Проверено на «Сивухине»:
MiniLM не находил абзац про энтропию, e5 находил.

Тонкости e5:

- нужны префиксы: `query: ` для вопроса, `passage: ` для фрагмента. Поэтому
  векторы считаются явно и передаются в `add(embeddings=...)`, а
  `embedding_function` не используется (Chroma молча подставит свою модель,
  если векторов нет).
- коллекции: `library__e5s` и `episodes__e5s`, метрика `cosine`. Суффикс
  `e5s` — чтобы старые векторы от другой модели не смешивались с новыми;
  `migrate_legacy()` переносит эпизоды.
- у e5 высокий «пол» сходства (0.75 даже у несвязанного текста), поэтому
  абсолютный порог по косинусу не работает — см. следующий раздел.

Файлы модели: `assets/embed/multilingual-e5-small/`; переопределение —
`SOFIA_EMBED_DIR`.

## 5. Поиск: вектор + слова

`memory/book_search.py`. Одного косинуса мало: у многоязычных эмбеддингов
соседняя глава отстаёт от нужной на 0.03–0.04, и top-3 тащит «около темы».

Поэтому: Chroma отдаёт пул кандидатов (`LIBRARY_POOL=24`), затем
переранжирование.

```
score = 0.45 · косинус
      + 0.45 · перекрытие терминов запроса (вес по idf, стемминг)
      + 0.10 · бонус за точную фразу (если запрос длиннее 12 символов)
```

- `idf` считается по самому пулу: слово, встречающееся во всех кандидатах,
  веса не даёт.
- стемминг грубый (усечение до 6 символов): «импульса»/«импульс» сходятся,
  полноценный стеммер здесь не нужен.
- служебные слова выброшены, иначе «что такое» перевешивает термин.

**Отбор** (`select`): лучший балл минус `gap=0.22`, порог `min_score=0.52`
(либо косинус ≥ 0.88), не больше `LIBRARY_TOP_K=4` фрагментов и 2600 символов
на весь блок. Релевантные абзацы обычно идут плотной группой — всё, что
отстало сильнее, отбрасывается.

Проверка на живой библиотеке:

```
«второй закон Ньютона»     → Курс общей физики, с. 4–6 (3 фрагмента)
«рецепт борща»             → 0 фрагментов (молчит)
```

Пустой результат — правильный результат: лучше промолчать, чем подставить
цитату из другой книги.

## 6. Что попадает в промпт

```
[1] (Сивухин, Курс общей физики, с. 112)
<текст фрагмента>
```

Блок идёт отдельным сообщением перед вопросом; в ответе София ссылается на
источник, а не пересказывает без указания. Блок виден в `/state`
(`books.last_query`, `books.last_hits`) и в трассе (`SOFIA_LOG_LEVEL=DEBUG`).

## 7. Кеш промпта

`llama-server` умеет переиспользовать KV-кеш, если **начало** запроса
совпадает с предыдущим. Условия, которые для этого соблюдаются:

- `cache_prompt: True` в каждом запросе;
- системный блок стабилен: персона, правила языка и стиля не меняются от хода
  к ходу. Внутренний монолог идёт в трейлинг-сообщении ассистента, а не в
  системном тексте;
- меняется только то, что действительно ново: последняя реплика и, изредка,
  сводка истории.

Измерено на Gemma-4-E4B (llama-server b12606):

```
ход 1: 3.07 с   (префикс считается заново)
ход 2: 0.09 с   (687 токенов взяты из кеша)
```

Статистика кеша пишется в лог из `timings` ответа: `cache.n`, `cache.ms`,
`prompt.ms`. Если `cache.n` держится около нуля — префикс перестал быть
стабильным, это баг, а не «модель тормозит».

## 8. Сжатие контекста

`core/context.py`. Наивное скользящее окно (выкинуть старое сообщение)
убивает кеш: префикс меняется на каждом ходу, и все токены считаются заново.
Плюс теряются факты из начала разговора.

Поэтому — **редкое сжатие**:

- триггер: 8 сообщений (`COMPACT_TRIGGER_MESSAGES`) или превышение бюджета
  `min(6000, 35% · NUM_CTX)` токенов;
- последние 4 сообщения остаются дословно;
- всё, что старше, превращается в сводку на 3–6 пунктов (кто пользователь,
  что обсуждали, важные имена/числа/формулы, незакрытые вопросы), не более
  120 слов и 900 символов;
- сводка живёт в системном блоке и обновляется при следующем сжатии
  (предыдущая сводка подаётся модели как контекст, чтобы не терять старое);
- сводку делает `MODEL_EXTRACTOR_ACTIVE` (маленькая модель) с `num_predict=220`;
  если модель занята или ответила мусором — **резервная сводка без модели**
  (роли + начала реплик). Терять факты нельзя, поэтому сжатие никогда не
  «падает».

Между сжатиями префикс стабилен: кеш работает, история растёт справа.

`CONTEXT_BUDGET_TOKENS` переопределяет бюджет (0 — авто).

## 9. Настройки

```
LIBRARY_ENABLED=True
LIBRARY_TOP_K=4            # фрагментов в промпте
LIBRARY_POOL=24            # кандидатов из Chroma до переранжирования
LIBRARY_MIN_SCORE=0.52     # ниже — молчим
LIBRARY_OCR=auto           # auto | off
LIBRARY_CHUNK_SIZE=800
LIBRARY_CHUNK_OVERLAP=80
CONTEXT_BUDGET_TOKENS=0
```

Отдельные переменные: `SOFIA_EMBED_DIR` (папка модели), `TESSERACT_CMD`
(путь к tesseract.exe), `SOFIA_LOG_LEVEL=DEBUG` (трассы `books`/`context`/`cache`).

## 10. Что упаковано в exe

| Ресурс | Размер | Зачем |
|---|---|---|
| `assets/embed/multilingual-e5-small` | ~113 МБ | эмбеддинги для русского |
| `bin/tesseract` (rus+eng) | ~183 МБ | OCR сканов |
| `core/clips_rules`, `core/soar_rules` | мало | CLIPS и Soar |

Кэш загрузок HuggingFace (`.cache`) внутрь не копируется. `build.ps1` сам
готовит оба ресурса: если модели нет — скачивает её, если нет Tesseract —
ставит через winget и докачивает `rus.traineddata`.

## 11. Проверка

```
# юнит-тесты (без GPU): чистка, чанкинг, переранжирование, сжатие, упаковка
.venv/Scripts/python.exe -m pytest tests/unit/test_library_clean.py \
    tests/unit/test_library_chunking.py tests/unit/test_book_search.py \
    tests/unit/test_context.py tests/unit/test_embedder.py tests/unit/test_bundling.py -q
```

Живые прогоны: индексация настоящей книги и вопрос по ней (`/state` →
`books.last_hits`), затем повторный вопрос — в логе должен появиться
`cache.n > 0`.

## 12. Чего здесь нет

- **Обучения на книгах внутри программы.** Веса не меняются: знания приходят
  через поиск. LoRA (стиль) обучается отдельно и в `.exe` не входит.
- **Формул в ответе.** Модель видит текст, но не понимает вёрстку формул и
  графики: «выведи формулу (3.14)» может кончиться пересказом словами.
- **EPUB/DOCX.** Индексируются только PDF (`TODO` в `ingest_file`).
- **Таблиц и графиков.** Картинки в книгах не распознаются — только текст.
