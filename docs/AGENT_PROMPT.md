## Ключевое правило: Target ≠ Dev

Ты пишешь код на **мощной VDS**, но он **обязан работать на слабом ноутбуке**:

| | Dev (ты здесь) | Target (ноутбук пользователя) |
|---|---|---|
| GPU | 8 GB (может быть Tesla/etc) | RTX 5050 8 GB |
| RAM | 75 GB | 16 GB |
| CPU | 8 ядер серверных | Ryzen 7 260AI (мобильный) |
| OS | Linux | Windows 11 |
| iGPU | — | AMD 780M (512 MB shared) |

**Никогда** не предполагай, что на target есть 75 GB RAM. Любое решение должно укладываться в **16 GB RAM** и **8 GB VRAM**.

2. **Записывать голос** — микрофон VDS не используется, образцы голоса на ноутбуке
3. **Тестировать XTTS с реальными образцами** — голосовые файлы не на VDS
4. **Тестировать GUI/браузер на Windows** — ты на Linux без GUI

## Как проверить, что код влезет в ноутбук

Перед каждым коммитом:

```bash
# 1. Синтаксис и импорты
python -m py_compile core/*.py memory/*.py modules/*.py main.py

# 2. Бенчмарк (проверка VRAM/RAM/скорости)
python scripts/benchmark_target.py

# 3. Линтинг (если есть)
# ruff check . || flake8 .
```

Если `benchmark_target.py` падает по RAM/VRAM — код не готов к деплою.

## Ограничения, которые ты обязан соблюдать

### VRAM (8 GB)
- qwen3:4b: ~5.7 GB в VRAM
- XTTS v2: ~2 GB (загружается по требованию, выгружается после)
- Остальное (FER, GUI, etc): в RAM, не в VRAM
- **Запас**: 0.5 GB на системные нужды
- **Нельзя**: держать 4b + 8b + XTTS одновременно в VRAM

### RAM (16 GB)
- Windows 11 + фон: ~4-5 GB
- Ollama (KV-кэш, если модель в VRAM — минимум): ~1 GB
- Chroma (векторная БД): ~1-2 GB при 1000 чанков
- Python + FastAPI + зависимости: ~1-2 GB
- XTTS (если на CPU): ~2-3 GB
- **Свободно**: ~4-6 GB
- **Нельзя**: загружать модели в RAM одновременно (используй lazy loading)

### CPU
- Не нагружай все 8 ядер постоянно — это ноутбук, будет греться и троттлить
- Тяжёлые вычисления (LLM, TTS) — только на GPU
- Чанкинг книг, эмбеддинги — можно на CPU, но порционно

### Контекст LLM
- Максимум: 32768 токенов (num_ctx)
- Рекомендуется: 8192-16384 для скорости
- Не гонись за 128k — не влезет в VRAM
