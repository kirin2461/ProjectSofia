# Архитектура Project Sofia

## Две среды

```
┌─────────────────────────────────────────────────────────────┐
│  DEV (VDS)                                                  │
│  8 CPU / 8 GB GPU / 75 GB RAM                               │
│  Linux • Полный набор инструментов • Быстрая сборка         │
│                                                             │
│  Здесь: разработка, тестирование, CI, сборка релиза         │
└────────────────────┬────────────────────────────────────────┘
                     │
                     │ git push / pull
                     │
                     ▼
┌─────────────────────────────────────────────────────────────┐
│  TARGET (Ноутбук)                                           │
│  RTX 5050 8 GB / 16 GB RAM / Ryzen 7 260AI                  │
│  Windows 11 • Ollama локально • Ограниченные ресурсы        │
│                                                             │
│  Здесь: работает ассистент, голос, память, жизнь            │
└─────────────────────────────────────────────────────────────┘
```

## Поток данных (Target)

```
Пользователь (WebSocket / браузер / Telegram)
    ↓
FastAPI Endpoint (localhost:8000)
    ├── Экстрактор (qwen3:1.7b) → структурированные факты
    ├── CLIPS: предфильтр безопасности (мгновенно)
    ├── Memory: retrieval эпизодов + библиотека (bge-m3, CPU)
    ├── Монолог (qwen3:4b, stream=False, think=True)
    ├── Ответ (qwen3:4b, stream=True) → WebSocket
    └── Критик (qwen3:4b, stream=False, think=True)
        → Обновление PAD, XP, запись эпизода
```

## Компоненты

| Компонент | Роль | Модель | Где работает |
|---|---|---|---|
| Экстрактор | Диалог → факты | qwen3:1.7b | Target GPU |
| Мозг | Монолог, эмоции, генерация | qwen3:4b | Target GPU |
| Критик | Проверка ответа | qwen3:4b | Target GPU |
| Эмбеддер | Векторизация памяти, книг | bge-m3 | Target CPU (или GPU) |
| CLIPS | Безопасность, жизненный цикл | — | Target CPU |
| SOAR | Цели, импассы, чанкинг | — | Target CPU (этап 5) |

## Память

- **Эпизодическая**: события диалога, дневники, критика
- **Семантическая (библиотека)**: книги из `data/library/`, индексируются через bge-m3
- **Процедурная**: навыки + чанкинг SOAR

## Ограничения Target

| Ресурс | Лимит | Как учитывается |
|---|---|---|
| GPU VRAM | 8 ГБ | qwen3:4b (~5.7 GB) + запас под XTTS и FER |
| RAM | 16 ГБ | 780M ограничена 512 МБ, Ollama в VRAM, остальное под систему |
| CPU | 8 ядер (мобильные) | Все тяжёлые вычисления на GPU |
| Диск | SSD | Chroma-база, книги, логи — всё локально |

## Dev → Target

1. На VDS пишется код, тестируется логика
2. `scripts/benchmark_target.py` проверяет: "увлезет ли в ноутбук?"
3. Git push → pull на ноутбук
4. Тест на реальном железе

## Голос

XTTS v2 (~2 GB модель) загружается в VRAM по требованию, выгружается после генерации. На Target это критично — 8 GB VRAM заполняется полностью при одновременной работе LLM + XTTS.
