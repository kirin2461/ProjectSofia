# Архитектура Project Sofia

## Две среды

```
┌─────────────────────────────────────────────────────────────┐
│  DEV (VDS)                                                  │
│  8 CPU / 8 GB GPU / 8 GB RAM / 75 GB SSD                    │
│  Linux • Полный набор инструментов • Быстрая сборка         │
│                                                             │
│  Здесь: разработка, тестирование, CI, сборка релиза         │
│  ⚠️ Осторожно: всего 8 GB RAM — меньше, чем на ноутбуке    │
└────────────────────┬────────────────────────────────────────┘
                     │
                     │ git push / pull
                     │
                     ▼
┌─────────────────────────────────────────────────────────────┐
│  TARGET (Ноутбук)                                           │
│  RTX 5050 8 GB VRAM / 16 GB RAM / Ryzen 7 260AI            │
│  Windows 11 • Ollama локально • Ограниченные ресурсы        │
│                                                             │
│  Здесь: работает ассистент, голос, память, жизнь            │
└─────────────────────────────────────────────────────────────┘
```

**Ключевой момент:** ноутбук (target) имеет **в 2 раза больше RAM**, чем VDS (dev). Это значит:
- На VDS нельзя запускать полный стек одновременно (8 GB RAM не хватит)
- Тестирование интеграции лучше делать на ноутбуке
- На VDS — модульное тестирование по одному компоненту

## Поток данных (Target)

```
Пользователь (WebSocket / браузер / Telegram)
    ↓
FastAPI Endpoint (localhost:8000)
    ├── Экстрактор (qwen3:1.7b) → структурированные факты
    ├── CLIPS: предфильтр безопасности (мгновенно)
    ├── Memory: retrieval эпизодов + библиотека (bge-m3, CPU)
    ├── Монолог (qwen3:4b, stream=False, think=True)
    ├── Ответ (qwen3:4b, stream=True) → WebSocket
    └── Критик (qwen3:4b, stream=False, think=True)
        → Обновление PAD, XP, запись эпизода
```

## Компоненты

| Компонент | Роль | Модель | Где работает |
|---|---|---|---|
| Экстрактор | Диалог → факты | qwen3:1.7b | Target GPU |
| Мозг | Монолог, эмоции, генерация | qwen3:4b | Target GPU |
| Критик | Проверка ответа | qwen3:4b | Target GPU |
| Эмбеддер | Векторизация памяти, книг | bge-m3 | Target CPU |
| CLIPS | Безопасность, жизненный цикл | — | Target CPU |
| SOAR | Цели, импассы, чанкинг | — | Target CPU (этап 5) |

## Ограничения Target (ноутбук)

| Ресурс | Лимит | Как учитывается |
|---|---|---|
| GPU VRAM | 8 ГБ | qwen3:4b (~5.7 GB) + XTTS по требованию (~2 GB) |
| RAM | 16 ГБ | Windows + фон ~5 GB, доступно ~10 GB для приложения |
| CPU | 8 ядер (мобильные) | Все тяжёлые вычисления на GPU |
| Диск | SSD | Chroma, книги, логи — всё локально |

## Ограничения Dev (VDS)

| Ресурс | Лимит | Как учитывается |
|---|---|---|
| GPU VRAM | 8 ГБ | То же, что на ноутбуке — модели идентичны |
| RAM | **8 ГБ** | ⚠️ Меньше, чем на ноутбуке! Linux + система ~1-2 GB |
| Диск | 75 GB SSD | Много места для данных, но RAM узкое место |

## Dev → Target

1. На VDS пишется код, тестируется логика (по частям)
2. `scripts/benchmark_target.py` проверяет совместимость
3. Git push → pull на ноутбук
4. **Полное тестирование** на реальном железе (ноутбук)

## Голос

XTTS v2 (~2 GB модель) загружается в VRAM по требованию, выгружается после генерации. На обеих машинах 8 GB VRAM — критично не держать XTTS + LLM одновременно.
